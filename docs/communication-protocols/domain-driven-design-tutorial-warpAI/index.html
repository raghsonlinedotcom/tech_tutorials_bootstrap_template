Introduction to Domain-Driven Design

What is Domain-Driven Design?

Domain-Driven Design (DDD) is a software development approach that focuses on creating a shared understanding of the business domain between technical and non-technical stakeholders. It emphasizes modeling software to match the domain, using a ubiquitous language, and organizing code around business concepts.

Key Insight: DDD is not about technology—it's about aligning software with business needs through strategic and tactical patterns.
Why Use DDD?
  • Complexity Management: Handles complex business logic effectively
  • Shared Understanding: Creates common language between developers and domain experts
  • Flexibility: Adapts to changing business requirements
  • Modularity: Promotes clean separation of concerns
  • Maintainability: Easier to understand and modify over time

Strategic Design Patterns

Bounded Context

Definition: A boundary within which a particular domain model is defined and applicable. Each bounded context has its own ubiquitous language.

Real-World Example: E-Commerce Platform

In an e-commerce system, "Customer" means different things in different contexts:

  • Sales Context: Customer has orders, shipping address, payment methods
  • Support Context: Customer has tickets, communication history
  • Marketing Context: Customer has preferences, segments, campaign responses

Ubiquitous Language

Definition: A common language shared by developers and domain experts, used consistently in code, documentation, and conversations.

Real-World Example: Healthcare System

Scenario: Scheduling a medical appointment

❌ Without Ubiquitous Language:
  • Developer: "Create booking record"
  • Code: createRecord()
  • Database: bookings table
✅ With Ubiquitous Language:
  • Doctor: "Schedule appointment"
  • Code: scheduleAppointment()
  • Database: appointments table

Tactical Design Patterns

Entity

Definition: An object with a unique identity that persists over time, even when its attributes change.

Real-World Example: Customer Entity

A customer is identifiable by their unique ID, even if their name, address, or email changes.

package com.example.ecommerce.domain.model;

import org.springframework.data.annotation.Id;
import org.springframework.data.mongodb.core.mapping.Document;
import java.time.LocalDateTime;
import java.util.Objects;
import java.util.UUID;

/**
 * Customer Entity - Has unique identity (customerId)
 * Identity remains constant even when attributes change
 */
@Document(collection = "customers")
public class Customer {
    
    @Id
    private final String customerId;  // Unique identifier
    private String name;
    private Email email;              // Value Object
    private Address shippingAddress;  // Value Object
    private CustomerStatus status;
    private LocalDateTime createdAt;
    private LocalDateTime updatedAt;
    
    // Private constructor enforces creation through factory method
    private Customer(String customerId, String name, Email email) {
        this.customerId = customerId;
        this.name = Objects.requireNonNull(name, "Name cannot be null");
        this.email = Objects.requireNonNull(email, "Email cannot be null");
        this.status = CustomerStatus.ACTIVE;
        this.createdAt = LocalDateTime.now();
        this.updatedAt = LocalDateTime.now();
    }
    
    // Factory method
    public static Customer create(String name, Email email) {
        return new Customer(UUID.randomUUID().toString(), name, email);
    }
    
    // Business method: Update shipping address
    public void updateShippingAddress(Address newAddress) {
        this.shippingAddress = Objects.requireNonNull(newAddress);
        this.updatedAt = LocalDateTime.now();
        // Domain event could be raised here
    }
    
    // Business method: Deactivate customer
    public void deactivate() {
        if (this.status == CustomerStatus.INACTIVE) {
            throw new IllegalStateException("Customer is already inactive");
        }
        this.status = CustomerStatus.INACTIVE;
        this.updatedAt = LocalDateTime.now();
    }
    
    // Identity-based equals and hashCode
    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Customer)) return false;
        Customer customer = (Customer) o;
        return customerId.equals(customer.customerId);
    }
    
    @Override
    public int hashCode() {
        return Objects.hash(customerId);
    }
    
    // Getters
    public String getCustomerId() { return customerId; }
    public String getName() { return name; }
    public Email getEmail() { return email; }
    public Address getShippingAddress() { return shippingAddress; }
    public CustomerStatus getStatus() { return status; }
    public LocalDateTime getCreatedAt() { return createdAt; }
    public LocalDateTime getUpdatedAt() { return updatedAt; }
}

enum CustomerStatus {
    ACTIVE, INACTIVE, SUSPENDED
}
Key Points:
  • customerId is immutable and unique
  • Equality based on identity, not attributes
  • Business methods encapsulate domain logic
  • Factory method controls object creation

Value Object

Definition: An immutable object with no unique identity, defined entirely by its attributes. Two value objects with the same attributes are considered equal.

Real-World Example: Money Value Object

$50 USD is the same as any other $50 USD—it has no unique identity, only its amount and currency matter.

package com.example.ecommerce.domain.valueobject;

import java.math.BigDecimal;
import java.util.Currency;
import java.util.Objects;

/**
 * Money Value Object - Immutable, no identity
 * Equality based on attributes (amount + currency)
 */
public final class Money {
    
    private final BigDecimal amount;
    private final Currency currency;
    
    private Money(BigDecimal amount, Currency currency) {
        if (amount.compareTo(BigDecimal.ZERO) < 0) {
            throw new IllegalArgumentException("Amount cannot be negative");
        }
        this.amount = amount;
        this.currency = Objects.requireNonNull(currency, "Currency cannot be null");
    }
    
    public static Money of(BigDecimal amount, String currencyCode) {
        return new Money(amount, Currency.getInstance(currencyCode));
    }
    
    public static Money usd(double amount) {
        return new Money(BigDecimal.valueOf(amount), Currency.getInstance("USD"));
    }
    
    // Value object operations return new instances
    public Money add(Money other) {
        if (!this.currency.equals(other.currency)) {
            throw new IllegalArgumentException("Cannot add different currencies");
        }
        return new Money(this.amount.add(other.amount), this.currency);
    }
    
    public Money multiply(int multiplier) {
        return new Money(
            this.amount.multiply(BigDecimal.valueOf(multiplier)), 
            this.currency
        );
    }
    
    public boolean isGreaterThan(Money other) {
        if (!this.currency.equals(other.currency)) {
            throw new IllegalArgumentException("Cannot compare different currencies");
        }
        return this.amount.compareTo(other.amount) > 0;
    }
    
    // Attribute-based equals and hashCode
    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Money)) return false;
        Money money = (Money) o;
        return amount.equals(money.amount) && currency.equals(money.currency);
    }
    
    @Override
    public int hashCode() {
        return Objects.hash(amount, currency);
    }
    
    @Override
    public String toString() {
        return String.format("%s %s", currency.getSymbol(), amount);
    }
    
    public BigDecimal getAmount() { return amount; }
    public Currency getCurrency() { return currency; }
}

/**
 * Email Value Object - Validates and encapsulates email address
 */
public final class Email {
    
    private final String value;
    
    private Email(String value) {
        if (value == null || !isValid(value)) {
            throw new IllegalArgumentException("Invalid email address: " + value);
        }
        this.value = value.toLowerCase();
    }
    
    public static Email of(String email) {
        return new Email(email);
    }
    
    private static boolean isValid(String email) {
        return email.matches("^[A-Za-z0-9+_.-]+@[A-Za-z0-9.-]+\\.[A-Za-z]{2,}$");
    }
    
    public String getValue() { return value; }
    
    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Email)) return false;
        Email email = (Email) o;
        return value.equals(email.value);
    }
    
    @Override
    public int hashCode() {
        return Objects.hash(value);
    }
    
    @Override
    public String toString() {
        return value;
    }
}

Aggregate

Definition: A cluster of domain objects (entities and value objects) treated as a single unit. An aggregate has a root entity that controls access to its members and enforces invariants.

Real-World Example: Order Aggregate

An Order (aggregate root) contains OrderItems (entities). You cannot add/remove items directly—you must go through the Order.

┌─────────────────────────────────────────────────────┐ │ Order Aggregate (Aggregate Root) │ ├─────────────────────────────────────────────────────┤ │ Order Entity (Root) │ │ • orderId: UUID │ │ • customerId: UUID │ │ • status: OrderStatus │ │ • totalAmount: Money │ │ • createdAt: DateTime │ │ │ │ ┌────────────────────────────────────────────┐ │ │ │ OrderItem Entity (inside aggregate) │ │ │ │ • orderItemId: UUID │ │ │ │ • productId: UUID │ │ │ │ • quantity: int │ │ │ │ • price: Money │ │ │ └────────────────────────────────────────────┘ │ │ │ │ ┌────────────────────────────────────────────┐ │ │ │ ShippingInfo Value Object │ │ │ │ • address: Address │ │ │ │ • carrier: String │ │ │ │ • trackingNumber: String │ │ │ └────────────────────────────────────────────┘ │ │ │ │ Business Rules (Invariants): │ │ • Order must have at least one item │ │ • Total amount = sum of all item prices │ │ • Cannot modify order after it's shipped │ └─────────────────────────────────────────────────────┘ External objects can only: ✓ Reference Order by orderId ✗ Cannot directly access OrderItems ✗ Cannot create OrderItems independently 

package com.example.ecommerce.domain.aggregate;

import com.example.ecommerce.domain.valueobject.*;
import org.springframework.data.annotation.Id;
import org.springframework.data.mongodb.core.mapping.Document;
import java.time.LocalDateTime;
import java.util.*;

/**
 * Order Aggregate Root
 * Controls access to OrderItems and enforces business rules
 */
@Document(collection = "orders")
public class Order {
    
    @Id
    private final String orderId;
    private final String customerId;
    private final List items;  // Aggregate members
    private Money totalAmount;
    private OrderStatus status;
    private ShippingInfo shippingInfo;
    private final LocalDateTime createdAt;
    private LocalDateTime updatedAt;
    
    // Private constructor
    private Order(String orderId, String customerId) {
        this.orderId = orderId;
        this.customerId = customerId;
        this.items = new ArrayList<>();
        this.totalAmount = Money.usd(0);
        this.status = OrderStatus.PENDING;
        this.createdAt = LocalDateTime.now();
        this.updatedAt = LocalDateTime.now();
    }
    
    // Factory method
    public static Order create(String customerId) {
        return new Order(UUID.randomUUID().toString(), customerId);
    }
    
    // Business method: Add item to order
    public void addItem(String productId, int quantity, Money price) {
        validateOrderCanBeModified();
        
        // Check if product already in order
        Optional existing = items.stream()
            .filter(item -> item.getProductId().equals(productId))
            .findFirst();
            
        if (existing.isPresent()) {
            existing.get().increaseQuantity(quantity);
        } else {
            items.add(new OrderItem(
                UUID.randomUUID().toString(), 
                productId, 
                quantity, 
                price
            ));
        }
        
        recalculateTotal();
        this.updatedAt = LocalDateTime.now();
    }
    
    // Business method: Remove item
    public void removeItem(String orderItemId) {
        validateOrderCanBeModified();
        
        items.removeIf(item -> item.getOrderItemId().equals(orderItemId));
        
        if (items.isEmpty()) {
            throw new IllegalStateException("Order must have at least one item");
        }
        
        recalculateTotal();
        this.updatedAt = LocalDateTime.now();
    }
    
    // Business method: Update shipping info
    public void setShippingInfo(Address address, String carrier) {
        validateOrderCanBeModified();
        this.shippingInfo = new ShippingInfo(address, carrier);
        this.updatedAt = LocalDateTime.now();
    }
    
    // Business method: Submit order
    public void submit() {
        if (items.isEmpty()) {
            throw new IllegalStateException("Cannot submit empty order");
        }
        if (shippingInfo == null) {
            throw new IllegalStateException("Shipping info required");
        }
        if (status != OrderStatus.PENDING) {
            throw new IllegalStateException("Can only submit pending orders");
        }
        
        this.status = OrderStatus.SUBMITTED;
        this.updatedAt = LocalDateTime.now();
        
        // Raise domain event
        // DomainEventPublisher.publish(new OrderSubmittedEvent(this.orderId));
    }
    
    // Business method: Ship order
    public void ship(String trackingNumber) {
        if (status != OrderStatus.SUBMITTED) {
            throw new IllegalStateException("Can only ship submitted orders");
        }
        
        this.shippingInfo.setTrackingNumber(trackingNumber);
        this.status = OrderStatus.SHIPPED;
        this.updatedAt = LocalDateTime.now();
    }
    
    // Private method: Enforce invariant
    private void validateOrderCanBeModified() {
        if (status == OrderStatus.SHIPPED || status == OrderStatus.DELIVERED) {
            throw new IllegalStateException(
                "Cannot modify order in " + status + " status"
            );
        }
    }
    
    // Private method: Maintain total consistency
    private void recalculateTotal() {
        this.totalAmount = items.stream()
            .map(OrderItem::getLineTotal)
            .reduce(Money.usd(0), Money::add);
    }
    
    // Return unmodifiable list to protect aggregate boundary
    public List getItems() {
        return Collections.unmodifiableList(items);
    }
    
    // Getters
    public String getOrderId() { return orderId; }
    public String getCustomerId() { return customerId; }
    public Money getTotalAmount() { return totalAmount; }
    public OrderStatus getStatus() { return status; }
    public ShippingInfo getShippingInfo() { return shippingInfo; }
}

Domain Service

Definition: A stateless service that contains domain logic that doesn't naturally fit within an entity or value object, often involving multiple aggregates.

Real-World Example: Fund Transfer

Transferring money between two bank accounts involves two Account aggregates and doesn't belong to either one exclusively.

package com.example.ecommerce.domain.service;

import com.example.ecommerce.domain.aggregate.Order;
import com.example.ecommerce.domain.model.Product;
import com.example.ecommerce.domain.repository.ProductRepository;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

/**
 * PricingService - Domain Service
 * Handles complex pricing logic involving multiple entities
 */
@Service
public class PricingService {
    
    private final ProductRepository productRepository;
    
    public PricingService(ProductRepository productRepository) {
        this.productRepository = productRepository;
    }
    
    /**
     * Calculate order total with discounts and tax
     * Involves Order aggregate, Product entities, and business rules
     */
    @Transactional(readOnly = true)
    public Money calculateOrderTotal(Order order, DiscountPolicy discountPolicy) {
        Money subtotal = order.getTotalAmount();
        
        // Apply quantity discounts
        Money afterDiscount = applyQuantityDiscounts(order, subtotal);
        
        // Apply customer-specific discounts
        Money afterCustomerDiscount = discountPolicy.apply(afterDiscount, order.getCustomerId());
        
        // Calculate and add tax
        Money tax = calculateTax(afterCustomerDiscount, order.getShippingInfo().getAddress());
        
        return afterCustomerDiscount.add(tax);
    }
    
    private Money applyQuantityDiscounts(Order order, Money subtotal) {
        // Business logic: 10% off for orders > $100, 20% off for orders > $500
        if (subtotal.isGreaterThan(Money.usd(500))) {
            return subtotal.multiply(0.80);
        } else if (subtotal.isGreaterThan(Money.usd(100))) {
            return subtotal.multiply(0.90);
        }
        return subtotal;
    }
    
    private Money calculateTax(Money amount, Address address) {
        // Tax calculation based on shipping address
        double taxRate = TaxRateCalculator.getRateForState(address.getState());
        return Money.of(
            amount.getAmount().multiply(BigDecimal.valueOf(taxRate)),
            amount.getCurrency().getCurrencyCode()
        );
    }
}

/**
 * OrderFulfillmentService - Domain Service
 * Coordinates order fulfillment across inventory and shipping
 */
@Service
public class OrderFulfillmentService {
    
    private final InventoryService inventoryService;
    private final ShippingService shippingService;
    
    public OrderFulfillmentService(InventoryService inventoryService, 
                                  ShippingService shippingService) {
        this.inventoryService = inventoryService;
        this.shippingService = shippingService;
    }
    
    /**
     * Process order fulfillment
     * Domain logic spanning multiple bounded contexts
     */
    @Transactional
    public FulfillmentResult fulfillOrder(Order order) {
        // Check inventory availability
        boolean inventoryAvailable = inventoryService.checkAvailability(order);
        
        if (!inventoryAvailable) {
            return FulfillmentResult.failure("Insufficient inventory");
        }
        
        // Reserve inventory
        inventoryService.reserve(order);
        
        try {
            // Create shipment
            String trackingNumber = shippingService.createShipment(order);
            
            // Update order with tracking
            order.ship(trackingNumber);
            
            return FulfillmentResult.success(trackingNumber);
            
        } catch (Exception e) {
            // Compensating action: release inventory
            inventoryService.release(order);
            throw e;
        }
    }
}

class FulfillmentResult {
    private final boolean success;
    private final String message;
    private final String trackingNumber;
    
    private FulfillmentResult(boolean success, String message, String trackingNumber) {
        this.success = success;
        this.message = message;
        this.trackingNumber = trackingNumber;
    }
    
    static FulfillmentResult success(String trackingNumber) {
        return new FulfillmentResult(true, "Order fulfilled successfully", trackingNumber);
    }
    
    static FulfillmentResult failure(String message) {
        return new FulfillmentResult(false, message, null);
    }
    
    public boolean isSuccess() { return success; }
    public String getMessage() { return message; }
    public String getTrackingNumber() { return trackingNumber; }
}

Repository

Definition: An abstraction that provides access to aggregates, mimicking a collection interface. Hides persistence details from the domain layer.

Real-World Example: Order Repository

The domain treats OrderRepository as if it's working with an in-memory collection of orders, without knowing about MongoDB, SQL, or any persistence technology.

/**
 * OrderRepositoryImpl (in infrastructure layer)

 */
@Repository
public interface OrderRepositoryImpl extends MongoRepository, OrderRepository {

    @Override
    List findByStatus(OrderStatus status);
    
    @Query("{ 'status': 'PENDING', 'createdAt': { $lt: ?0 } }")
    @Override
    List findPendingOrdersOlderThan(int hours) {
        LocalDateTime cutoffTime = LocalDateTime.now().minusHours(hours);
        return findPendingOrdersCreatedBefore(cutoffTime);
    }
    
    List findPendingOrdersCreatedBefore(LocalDateTime dateTime);
    
    @Override
    boolean existsByCustomerIdAndStatus(String customerId, OrderStatus status);
}
Repository Pattern Benefits:
  • Domain layer doesn't know about MongoDB, SQL, etc.
  • Easy to swap persistence technology
  • Simplified testing with mock repositories
  • Queries expressed in domain terms

package com.example.ecommerce.infrastructure.messaging;

import com.example.ecommerce.domain.event.DomainEvent;
import org.springframework.kafka.core.KafkaTemplate;
import org.springframework.stereotype.Component;
import com.fasterxml.jackson.databind.ObjectMapper;

/**
 * DomainEventPublisher - Infrastructure component
 * Publishes domain events to Kafka
 */
@Component
public class DomainEventPublisher {
    
    private final KafkaTemplate kafkaTemplate;
    private final ObjectMapper objectMapper;
    
    public DomainEventPublisher(KafkaTemplate kafkaTemplate,
                               ObjectMapper objectMapper) {
        this.kafkaTemplate = kafkaTemplate;
        this.objectMapper = objectMapper;
    }
    
    public void publish(DomainEvent event) {
        try {
            String topic = "domain-events." + event.getEventType();
            String eventJson = objectMapper.writeValueAsString(event);
            
            kafkaTemplate.send(topic, event.getEventId(), eventJson);
            
            System.out.println("Published event: " + event.getEventType() + 
                             " (ID: " + event.getEventId() + ")");
        } catch (Exception e) {
            throw new RuntimeException("Failed to publish domain event", e);
        }
    }
}

import com.example.ecommerce.domain.event.OrderSubmittedEvent;

import org.springframework.stereotype.Component;

/**
 * OrderEventHandler - Application Service
 * Listens to domain events and triggers side effects
 */
@Component
public class OrderEventHandler {
    
    private final EmailService emailService;
    private final InventoryService inventoryService;
    private final AnalyticsService analyticsService;
    
    public OrderEventHandler(EmailService emailService,
                            InventoryService inventoryService,
                            AnalyticsService analyticsService) {
        this.emailService = emailService;
        this.inventoryService = inventoryService;
        this.analyticsService = analyticsService;
    }
    
    @KafkaListener(topics = "domain-events.OrderSubmitted", groupId = "order-service")
    public void handleOrderSubmitted(String eventJson) {
        try {
            OrderSubmittedEvent event = parseEvent(eventJson, OrderSubmittedEvent.class);
            
            // Send confirmation email
            emailService.sendOrderConfirmation(event.getOrderId(), event.getCustomerId());
            
            // Reserve inventory
            inventoryService.reserveForOrder(event.getOrderId());
            
            // Update analytics
            analyticsService.recordOrderSubmitted(event);
            
        } catch (Exception e) {
            // Handle error, retry logic, dead letter queue, etc.
            System.err.println("Error handling OrderSubmittedEvent: " + e.getMessage());
        }
    }
    
    @KafkaListener(topics = "domain-events.OrderShipped", groupId = "order-service")
    public void handleOrderShipped(String eventJson) {
        OrderShippedEvent event = parseEvent(eventJson, OrderShippedEvent.class);
        
        // Send shipping notification
        emailService.sendShippingNotification(
            event.getOrderId(), 
            event.getCustomerId(),
            event.getTrackingNumber()
        );
    }
    
    private  T parseEvent(String json, Class eventClass) {
        // Parse JSON to event object
        return new ObjectMapper().readValue(json, eventClass);
    }
}

package com.example.ecommerce.application.service;

import com.example.ecommerce.application.dto.*;
import com.example.ecommerce.domain.aggregate.Order;
import com.example.ecommerce.domain.event.*;
import com.example.ecommerce.domain.repository.OrderRepository;
import com.example.ecommerce.domain.valueobject.*;
import com.example.ecommerce.infrastructure.messaging.DomainEventPublisher;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;
import java.util.List;
import java.util.stream.Collectors;

/**
 * OrderApplicationService - Application Layer
 * Coordinates use cases, manages transactions
 */
@Service
@Transactional
public class OrderApplicationService {
    
    private final OrderRepository orderRepository;
    private final DomainEventPublisher eventPublisher;
    
    public OrderApplicationService(OrderRepository orderRepository,
                                  DomainEventPublisher eventPublisher) {
        this.orderRepository = orderRepository;
        this.eventPublisher = eventPublisher;
    }
    
    /**
     * Create new order (CREATE)
     */
    public OrderResponse createOrder(CreateOrderRequest request) {
        // Create aggregate
        Order order = Order.create(request.customerId());
        
        // Set shipping info
        Address address = Address.of(
            request.shippingAddress().street(),
            request.shippingAddress().city(),
            request.shippingAddress().state(),
            request.shippingAddress().zipCode(),
            request.shippingAddress().country()
        );
        order.setShippingInfo(address, "USPS");
        
        // Save
        orderRepository.save(order);
        
        return toResponse(order);
    }
    
    /**
     * Get order by ID (READ)
     */
    @Transactional(readOnly = true)
    public OrderResponse getOrder(String orderId) {
        Order order = orderRepository.findById(orderId)
            .orElseThrow(() -> new IllegalArgumentException("Order not found: " + orderId));
        
        return toResponse(order);
    }
    
    /**
     * Get customer orders (READ)
     */
    @Transactional(readOnly = true)
    public List getCustomerOrders(String customerId) {
        List orders = orderRepository.findByCustomerId(customerId);
        
        return orders.stream()
            .map(this::toResponse)
            .collect(Collectors.toList());
    }
    
    /**
     * Add item to order (UPDATE)
     */
    public OrderResponse addItemToOrder(String orderId, AddOrderItemRequest request) {
        // Load aggregate
        Order order = orderRepository.findById(orderId)
            .orElseThrow(() -> new IllegalArgumentException("Order not found: " + orderId));
        
        // Business logic in aggregate
        Money price = Money.of(
            BigDecimal.valueOf(request.price()), 
            request.currency()
        );
        order.addItem(request.productId(), request.quantity(), price);
        
        // Save modified aggregate
        orderRepository.save(order);
        
        return toResponse(order);
    }
    
    /**
     * Submit order (UPDATE)
     */
    public OrderResponse submitOrder(String orderId) {
        Order order = orderRepository.findById(orderId)
            .orElseThrow(() -> new IllegalArgumentException("Order not found: " + orderId));
        
        // Business logic
        order.submit();
        
        // Save
        orderRepository.save(order);
        
        // Publish domain event
        OrderSubmittedEvent event = new OrderSubmittedEvent(
            order.getOrderId(),
            order.getCustomerId(),
            order.getTotalAmount(),
            order.getItems().size()
        );
        eventPublisher.publish(event);
        
        return toResponse(order);
    }
    
    /**
     * Ship order (UPDATE)
     */
    public OrderResponse shipOrder(String orderId, ShipOrderRequest request) {
        Order order = orderRepository.findById(orderId)
            .orElseThrow(() -> new IllegalArgumentException("Order not found: " + orderId));
        
        // Business logic
        order.ship(request.trackingNumber());
        
        // Save
        orderRepository.save(order);
        
        // Publish event
        OrderShippedEvent event = new OrderShippedEvent(
            order.getOrderId(),
            order.getCustomerId(),
            request.trackingNumber(),
            request.carrier()
        );
        eventPublisher.publish(event);
        
        return toResponse(order);
    }
    
    /**
     * Cancel order (DELETE)
     */
    public void cancelOrder(String orderId) {
        Order order = orderRepository.findById(orderId)
            .orElseThrow(() -> new IllegalArgumentException("Order not found: " + orderId));
        
        // Soft delete or status change
        orderRepository.delete(order);
    }
    
    /**
     * Convert domain model to DTO
     */
    private OrderResponse toResponse(Order order) {
        List items = order.getItems().stream()
            .map(item -> new OrderItemDto(
                item.getOrderItemId(),
                item.getProductId(),
                item.getQuantity(),
                item.getPrice().getAmount().doubleValue()
            ))
            .collect(Collectors.toList());
        
        return new OrderResponse(
            order.getOrderId(),
            order.getCustomerId(),
            items,
            order.getTotalAmount().getAmount().doubleValue(),
            order.getStatus().name(),
            order.getCreatedAt(),
            order.getUpdatedAt()
        );
    }
}

Benefits of Kafka with DDD
  • Decoupling: Producers don't need to know about consumers
  • Scalability: Multiple consumers can process events independently
  • Reliability: Events are persisted and can be replayed
  • Ordering: Events within a partition maintain order
  • Event Sourcing: Complete audit trail of domain changes
Important Considerations:
  • Use idempotent consumers to handle duplicate events
  • Implement error handling and dead letter queues
  • Monitor consumer lag and processing times
  • Version your event schemas for backward compatibility

DDD Bounded Contexts as Microservices

Each bounded context can become an independent microservice with its own database and deployment.

Key Microservices Principles with DDD:
  • Bounded Context = Microservice: Each context becomes a deployable service
  • Database per Service: Each service has its own database (polyglot persistence)
  • Event-Driven Communication: Services communicate via domain events
  • API Gateway: Single entry point for client applications
  • Service Discovery: Services register and discover each other dynamically
  • Distributed Tracing: Monitor requests across services

Pros & Cons of Domain-Driven Design

Advantages
  • Better Business Alignment: Software matches business needs precisely
  • Ubiquitous Language: Shared vocabulary reduces miscommunication
  • Modularity: Clear boundaries make code easier to understand
  • Maintainability: Business logic centralized in domain layer
  • Testability: Domain logic can be tested in isolation
  • Scalability: Bounded contexts can scale independently
  • Flexibility: Easy to adapt to changing requirements
  • Team Organization: Teams can work on different contexts independently
Disadvantages
  • Complexity: Higher initial learning curve and setup cost
  • Over-Engineering: Not suitable for simple CRUD applications
  • Team Skill: Requires experienced developers familiar with DDD
  • Time Investment: Upfront modeling and design takes time
  • Distributed Challenges: Eventual consistency, distributed transactions
  • More Code: Value objects, aggregates add boilerplate
  • Context Mapping: Integration between contexts can be complex
  • Domain Expert Access: Requires ongoing collaboration with business
When to Use DDD:
  • ✅ Complex business logic with many rules and workflows
  • ✅ Long-term projects that will evolve over time
  • ✅ Multiple teams working on different parts of the system
  • ✅ Access to domain experts for collaboration
  • ❌ Simple CRUD applications with minimal business logic
  • ❌ Short-term projects or prototypes
  • ❌ Small teams without DDD experience
