Introduction - Why jq Was Invented

The Problem jq Solves

Before jq, working with JSON data on the command line was painful and error-prone.

Challenges Before jq
  • No native JSON parsing in shell scripts
  • Complex regex patterns needed for extraction
  • Writing custom scripts for simple tasks
  • No standard tool for JSON manipulation
  • Brittle parsing prone to errors
  • Difficulty handling nested structures
Solutions with jq
  • Native JSON understanding
  • Declarative filter syntax
  • One-liner solutions for common tasks
  • Industry-standard tool
  • Type-safe operations
  • Deep nested data handling
Historical Context

jq was created by Stephen Dolan in 2012 as a response to the growing prevalence of JSON in web APIs, configuration files, and data interchange formats. As JSON became ubiquitous in software development, the need for a specialized command-line tool that could efficiently parse, filter, and transform JSON data became apparent.

Design Philosophy: jq was designed to be like sed for JSON data - a simple, composable tool that does one thing exceptionally well: processing JSON from the command line.

Architecture, Ecosystem & Toolkit

jq Architecture Overview

jq is built as a streaming JSON processor with a clear separation of concerns:

Core Components
  • Lexer: Tokenizes input JSON
  • Parser: Builds Abstract Syntax Tree (AST)
  • Compiler: Converts filters to bytecode
  • Runtime: Executes compiled filters
  • Memory Manager: Handles JSON values
Design Patterns
  • Streaming: Process large files efficiently
  • Functional: Immutable data transformations
  • Composable: Filters as building blocks
  • Lazy Evaluation: Compute only when needed
  • Generator-based: Multiple outputs per input
Processing Pipeline
  1. Input: JSON data from stdin, file, or argument
  2. Parsing: JSON text converted to internal representation
  3. Filter Compilation: jq filter expression compiled to bytecode
  4. Execution: Filter applied to parsed JSON
  5. Output: Results serialized to JSON and written to stdout

Basic Usage & Syntax

Command Structure
jq [options] <filter> [file...]
Common Options & Flags
Option Description Example
-r, --raw-output Output raw text, not JSON strings jq -r '.name'
-c, --compact-output Compact JSON output (single line) jq -c '.'
-s, --slurp Read entire input stream into array jq -s '.'
-n, --null-input Don't read input; filter starts with null jq -n '{a:1}'
-e, --exit-status Set exit status based on output jq -e '.error'
-f, --from-file Read filter from file jq -f filter.jq
-M, --monochrome-output Disable colored output jq -M '.'
-C, --color-output Force colored output jq -C '.'
--tab Use tabs for indentation jq --tab '.'
--indent n Use n spaces for indentation jq --indent 2 '.'
--arg name value Pass string variable to filter jq --arg key "val" '.'
--argjson name json Pass JSON variable to filter jq --argjson num 42 '.'
--slurpfile var file Read JSON file into variable jq --slurpfile data d.json '.'
Simple Example

Let's start with the most basic usage - pretty-printing JSON:

echo '{"name":"Alice","age":30}' | jq '.'

Output:

{ "name": "Alice", "age": 30 }
Tip: The . filter is the identity filter - it outputs the input unchanged but pretty-printed.

Filters & Operations

jq's power comes from its extensive set of filters and operations for manipulating JSON data.

Identity Filter
jq '.' company.json

Result: Returns the entire JSON unchanged

Object Index
jq '.company.name' company.json
"TechCorp Solutions"
Array Index
jq '.company.departments[0].name' company.json
"Engineering"
Array Slice
jq '.company.departments[0:2]' company.json

Result: Returns first two departments

Array Iterator
jq '.company.departments[].name' company.json
"Engineering" "Sales" "HR"
Optional Object Index
jq '.company.missing_field?' company.json

Result: Returns null instead of error if field doesn't exist

Recursive Descent
jq '.. | .name? | select(. != null)' company.json

Result: Finds all "name" fields at any depth

map - Transform each element
jq '.company.departments | map(.name)' company.json
["Engineering", "Sales", "HR"]
select - Filter elements
jq '.company.departments[] | select(.budget > 2000000)' company.json

Result: Departments with budget over 2M

sort / sort_by - Sort array
jq '.company.departments | sort_by(.budget) | reverse' company.json

Result: Departments sorted by budget (descending)

group_by - Group elements
jq '[.company.departments[].teams[].members[]] | group_by(.role)' company.json

Result: Employees grouped by role

unique / unique_by - Get unique values
jq '[.company.departments[].teams[].members[].skills[]] | unique' company.json

Result: All unique skills across company

flatten - Flatten nested arrays
jq '[.company.departments[].teams[].members[].skills] | flatten' company.json

Result: Flattened list of all skills

add - Sum or concatenate
jq '[.company.departments[].budget] | add' company.json
9500000
length - Array length
jq '.company.departments | length' company.json
3
min / max / min_by / max_by
jq '[.company.departments[].teams[].members[]] | max_by(.salary)' company.json

Result: Employee with highest salary

keys - Get object keys
jq '.company.financials.revenue | keys' company.json
["2022", "2023", "2024"]
values - Get object values
jq '.company.financials.revenue | values' company.json

Result: All revenue values

has - Check if key exists
jq '.company | has("departments")' company.json
true
del - Delete field
jq 'del(.company.departments[0].budget)' company.json

Result: Removes budget field from first department

with_entries - Transform key-value pairs
jq '.company.financials.revenue | with_entries(.value *= 1.1)' company.json

Result: Increase all revenue values by 10%

to_entries / from_entries - Convert format
jq '.company.financials.revenue | to_entries' company.json
[ {"key": "2024", "value": 15000000}, {"key": "2023", "value": 12000000}, {"key": "2022", "value": 9000000} ]
merge (+) - Merge objects
jq '.company.headquarters + {"timezone": "PST"}' company.json

Result: Adds timezone field to headquarters object

String Interpolation
jq '.company.departments[0] | "\(.name) has budget of $\(.budget)"' company.json
"Engineering has budget of $5000000"
split - Split string
jq '.company.headquarters.address.street | split(" ")' company.json
["123", "Innovation", "Drive"]
join - Join array to string
jq '.company.departments | map(.name) | join(", ")' company.json
"Engineering, Sales, HR"
startswith / endswith - String matching
jq '.company.departments[].name | select(startswith("Eng"))' company.json
"Engineering"
test - Regex match
jq '.company.departments[].name | select(test("^[ES]"))' company.json

Result: Department names starting with E or S

match - Regex with capture groups
jq '.company.headquarters.address.street | match("([0-9]+)")' company.json

Result: Captures the street number

gsub - Global substitution
jq '.company.name | gsub("Tech"; "Innovation")' company.json
"InnovationCorp Solutions"
ascii_downcase / ascii_upcase
jq '.company.name | ascii_upcase' company.json
"TECHCORP SOLUTIONS"
ltrimstr / rtrimstr - Trim prefix/suffix
jq '.company.name | rtrimstr(" Solutions")' company.json
"TechCorp"

Arithmetic Operations
# Calculate total payroll
jq '[.company.departments[].teams[].members[].salary] | add' company.json
630000
Comparison Operators
# High performers (rating >= 4.5)
jq '[.company.departments[].teams[].members[]] | map(select(.performance.rating >= 4.5))' company.json
Logical Operations (and, or, not)
# Senior Engineers with high ratings
jq '[.company.departments[].teams[].members[]] | map(select(.role == "Senior Engineer" and .performance.rating >= 4.5))' company.json
floor / ceil / round - Rounding
jq '.company.headquarters.address.coordinates.latitude | floor' company.json
37
if-then-else Conditionals
jq '.company.departments[0] | if .budget > 3000000 then "High Budget" else "Normal Budget" end' company.json
"High Budget"
any / all - Boolean aggregation
# Check if any department has budget over 4M
jq '[.company.departments[].budget > 4000000] | any' company.json
true

reduce - Aggregation
# Calculate average salary
jq '[.company.departments[].teams[].members[].salary] | reduce .[] as $s (0; . + $s) / length' company.json
paths - Get all paths
# Find all paths containing "salary"
jq '[paths | select(.[-1] == "salary")]' company.json
getpath / setpath - Dynamic path access
jq 'getpath(["company", "headquarters", "city"])' company.json
"San Francisco"
walk - Recursive transformation
# Convert all string values to uppercase
jq 'walk(if type == "string" then ascii_upcase else . end)' company.json
limit - Limit output
# Get first 2 employees
jq 'limit(2; .company.departments[].teams[].members[])' company.json
until - Loop until condition
jq '1 | until(. > 10; . * 2)' company.json
recurse - Recursive descent
# Find all objects with "name" field
jq '[recurse | objects | select(has("name"))]' company.json
Custom Functions
jq 'def avg: add / length; [.company.departments[].teams[].members[].salary] | avg' company.json

type - Get value type
jq '.company.departments | type' company.json
"array"
Type Checking Filters
# Filter only arrays
jq '.company | to_entries | map(select(.value | type == "array"))' company.json
tonumber / tostring
jq '.company.founded | tostring' company.json
"2015"
toarray / arrays - Array operations
jq '[.company | to_entries | .[].value | arrays]' company.json
@base64 / @base64d - Encoding
jq '.company.name | @base64' company.json
@uri / @csv / @tsv / @json / @html - Format conversions
jq '.company.departments | map([.name, .budget]) | @csv' company.json
"\"Engineering\",5000000\n\"Sales\",3000000\n\"HR\",1500000"
@sh - Shell escape
jq '.company.name | @sh' company.json
"'TechCorp Solutions'"

now - Current timestamp
jq -n 'now'
1737489994.123456
strftime / strptime - Date formatting
jq -n 'now | strftime("%Y-%m-%d %H:%M:%S")'
"2026-01-21 18:26:34"
todate / todateiso8601 - Date conversion
jq -n 'now | todateiso8601'
"2026-01-21T18:26:34Z"
Date arithmetic
# Days since founded
jq -n '"2015-01-01" | strptime("%Y-%m-%d") | mktime | (now - .) / 86400 | floor'

Use Case

HR needs a simple list of all employees with their salaries for payroll review.

Approach

Navigate through nested departments and teams to extract member data, then format it nicely.

jq '[.company.departments[].teams[].members[]] | map({name, salary})' company.json
[ { "name": "Alice Johnson", "salary": 150000 }, { "name": "Bob Williams", "salary": 120000 }, { "name": "Carol Martinez", "salary": 145000 }, { "name": "Emma Wilson", "salary": 130000 }, { "name": "Grace Lee", "salary": 85000 } ]
Data Extraction Flow ═══════════════════════════════════════ company.json │ └─── .company │ └─── .departments[] ────┐ │ │ ├─ [0] Engineering│ │ └─ .teams[] │ │ └─ .members[] ──┐ │ ├─ Alice │ │ └─ Bob │ │ │ ├─ [1] Sales │ Extract │ └─ .teams[] │ name & salary │ └─ .members[] ──┤ │ └─ Emma │ │ │ └─ [2] HR │ └─ .teams[] │ └─ .members[] ──┘ └─ Grace ↓ ┌──────────────────┐ │ Array of │ │ {name, salary} │ └──────────────────┘ 
@startuml
!theme plain
start
:Read company.json;
:Navigate to .company;
:Iterate .departments[];
partition "For Each Department" {
  :Iterate .teams[];
  partition "For Each Team" {
    :Iterate .members[];
    partition "For Each Member" {
      :Extract name;
      :Extract salary;
      :Create {name, salary} object;
    }
  }
}
:Collect all objects into array;
:Output JSON array;
stop
@enduml

Use Case

Management wants to identify engineers with performance ratings above 4.4 for bonus consideration.

Approach

Filter employees by role containing "Engineer" and performance rating >= 4.4.

jq '[.company.departments[].teams[].members[]] | 
  map(select(.role | contains("Engineer")) | 
  select(.performance.rating >= 4.4))' company.json
[ { "id": "e001", "name": "Alice Johnson", "role": "Senior Engineer", "salary": 150000, "skills": ["Python", "Go", "Docker"], "performance": { "rating": 4.5, "reviews": [...] } }, { "id": "e003", "name": "Carol Martinez", "role": "Senior Engineer", "salary": 145000, "skills": ["React", "TypeScript", "CSS"], "performance": { "rating": 4.7, "reviews": [...] } } ]
Filtering Pipeline ═══════════════════════════════════════ All Employees │ ├─ Alice (Engineer, 4.5) ──────┐ ├─ Bob (Engineer, 4.2) │ Filter: Role contains "Engineer" ├─ Carol (Engineer, 4.7) ──────┤ ├─ Emma (Manager, 4.4) │ └─ Grace (Recruiter, 4.3) │ ↓ ┌──────────────────────────┐ │ Engineers Only │ │ - Alice (4.5) │ │ - Bob (4.2) │ │ - Carol (4.7) │ └──────────────────────────┘ │ │ Filter: Rating >= 4.4 ↓ ┌──────────────────────────┐ │ High Performers │ │ - Alice (4.5) ✓ │ │ - Carol (4.7) ✓ │ └──────────────────────────┘ 
@startuml
!theme plain
start
:Collect all members into array;
partition "Filter Pipeline" {
  :For each employee;
  if (Role contains "Engineer"?) then (yes)
    if (Rating >= 4.4?) then (yes)
      :Include in results;
    else (no)
      :Exclude;
    endif
  else (no)
    :Exclude;
  endif
}
:Output filtered array;
stop

Use Case

Generate summary statistics for each department including employee count, total payroll, and average salary.

Approach

Map over departments, calculate aggregates for each team's members.

jq '.company.departments | map({
  department: .name,
  employee_count: ([.teams[].members[]] | length),
  total_payroll: ([.teams[].members[].salary] | add),
  avg_salary: (([.teams[].members[].salary] | add) / ([.teams[].members[]] | length) | round)
})' company.json

Important Nuances & Gotchas

jq filters can generate multiple outputs for a single input. This is powerful but can be surprising:

echo '[1,2,3]' | jq '.[]'
# Outputs three separate values:
# 1
# 2
# 3

To keep them as an array, wrap in [ ]:

echo '[1,2,3]' | jq '[.[]]'
# Outputs: [1,2,3]

Using ? makes field access optional and prevents errors:

# Without ?, errors if field missing
jq '.missing_field' file.json  # Error!

# With ?, returns null if missing
jq '.missing_field?' file.json  # null

This is crucial when processing heterogeneous JSON data.

By default, jq outputs JSON-formatted strings with quotes:

jq '.name' file.json
# Output: "Alice"

jq -r '.name' file.json
# Output: Alice

Use -r when piping to other commands or writing to files.

The pipe (|) chains filters sequentially, while comma (,) applies filters in parallel:

# Pipe: output of first goes to second
jq '.users | .[0]' file.json

# Comma: both applied to same input
jq '.users, .admins' file.json

Shell quoting can be tricky, especially with string interpolation:

# Single quotes protect from shell expansion
jq '.users[] | select(.name == "Alice")' file.json

# To use shell variables, use --arg
NAME="Alice"
jq --arg n "$NAME" '.users[] | select(.name == $n)' file.json

jq distinguishes between empty output, null, and false:

# Empty - generates no output
jq 'empty' file.json

# Null - outputs the JSON null value
jq 'null' file.json

# False - outputs boolean false
jq 'false' file.json

This matters for conditionals and filters like select.
