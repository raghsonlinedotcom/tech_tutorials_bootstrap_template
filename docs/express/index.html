1. Introduction

What is Express.js?

Express is a minimal and flexible Node.js web application framework providing a robust set of features for web and mobile applications.

Key Features
  • Robust routing with route parameters
  • Middleware architecture
  • Template engine support
  • HTTP utility methods
  • Content negotiation
  • High performance
Why Express?
  • Minimal and unopinionated
  • Huge middleware ecosystem
  • Industry standard (used by Netflix, Uber, PayPal)
  • Great for REST APIs
  • Active community
History

Created by TJ Holowaychuk in 2010, Express became the de facto Node.js web framework. Now maintained by the Node.js Foundation.

3. Hello World

Create app.js
const express = require('express');
const app = express();
const PORT = process.env.PORT || 3000;

app.get('/', (req, res) => {
  res.send('Hello World!');
});

app.listen(PORT, () => {
  console.log(`Server running on http://localhost:${PORT}`);
});

Explanation: This creates a basic Express server. express() initializes the app, app.get('/', ...) defines a route that responds to GET requests at the root path, and app.listen() starts the server on the specified port.

Run
node app.js
# Or with nodemon for auto-restart
nodemon app.js
Server running on http://localhost:3000

4. Routing

HTTP Methods
// GET - Retrieve data
app.get('/users', (req, res) => {
  res.json({ users: [] });
});

// POST - Create new resource
app.post('/users', (req, res) => {
  res.status(201).json({ message: 'User created' });
});

// PUT - Update entire resource
app.put('/users/:id', (req, res) => {
  res.json({ message: `User ${req.params.id} updated` });
});

// PATCH - Partial update
app.patch('/users/:id', (req, res) => {
  res.json({ message: `User ${req.params.id} partially updated` });
});

// DELETE - Remove resource
app.delete('/users/:id', (req, res) => {
  res.json({ message: `User ${req.params.id} deleted` });
});

Explanation: Express provides methods for all standard HTTP verbs. Each method corresponds to a different operation: GET retrieves data, POST creates new resources, PUT replaces entire resources, PATCH partially updates resources, and DELETE removes resources. The response uses res.json() to send JSON data back to the client.

Route Parameters
// Single parameter
app.get('/users/:userId', (req, res) => {
  const { userId } = req.params;
  res.json({ userId });
});

// Multiple parameters
app.get('/users/:userId/posts/:postId', (req, res) => {
  const { userId, postId } = req.params;
  res.json({ userId, postId });
});

// Optional parameters with regex
app.get('/flights/:from-:to', (req, res) => {
  res.json({ from: req.params.from, to: req.params.to });
});

Explanation: Route parameters are named URL segments that capture values from the URL. They are defined with colons (:paramName) and accessed via req.params. Multiple parameters can be used in a single route, and patterns like :from-:to allow for flexible URL structures.

Query Parameters
// URL: /search?q=express&page=1&limit=10
app.get('/search', (req, res) => {
  const { q, page = 1, limit = 10 } = req.query;
  res.json({ query: q, page, limit });
});

Explanation: Query parameters are optional key-value pairs appended to URLs after the ? symbol (e.g., /search?q=express&page=1). They are accessed through req.query and are ideal for filtering, pagination, and search functionality. Default values can be provided using destructuring.

Route Chaining
app.route('/book')
  .get((req, res) => {
    res.send('Get books');
  })
  .post((req, res) => {
    res.send('Add a book');
  })
  .put((req, res) => {
    res.send('Update book');
  });

Explanation: app.route() provides a chainable route API that reduces redundancy when defining multiple HTTP methods for the same path. Instead of repeating app.get('/book'), app.post('/book'), etc., you define the path once and chain the methods, making code cleaner and more maintainable.

5. Middleware

What is Middleware?

Functions with access to request, response, and next() function in the request-response cycle.

Application-Level Middleware
// Logger middleware
app.use((req, res, next) => {
  console.log(`${new Date().toISOString()} - ${req.method} ${req.url}`);
  next(); // Pass control to next middleware
});

// Specific path middleware
app.use('/api', (req, res, next) => {
  console.log('API route accessed');
  next();
});

Explanation: Middleware functions are executed sequentially for each request. The next() function passes control to the next middleware in the chain. Application-level middleware bound to the app object with app.use() runs for every request (if no path specified) or for requests to specific paths.

Built-in Middleware
// Parse JSON bodies
app.use(express.json());

// Parse URL-encoded bodies (form data)
app.use(express.urlencoded({ extended: true }));

// Serve static files
app.use(express.static('public'));
app.use('/uploads', express.static('uploads'));

Explanation: Express includes essential built-in middleware: express.json() parses incoming JSON payloads, express.urlencoded() parses URL-encoded form data (the extended: true option allows rich objects and arrays), and express.static() serves static files from a directory. These replace the need for body-parser in modern Express.

Third-Party Middleware
const morgan = require('morgan');
const cors = require('cors');
const helmet = require('helmet');
const compression = require('compression');

// HTTP request logger
app.use(morgan('dev'));

// Enable CORS - restrict origins in production
app.use(cors({
  origin: process.env.ALLOWED_ORIGINS?.split(',') || 'http://localhost:3000',
  methods: ['GET', 'POST', 'PUT', 'DELETE'],
  allowedHeaders: ['Content-Type', 'Authorization']
}));

// Security headers
app.use(helmet());

// Compress responses
app.use(compression());

Explanation: Third-party middleware extends Express functionality. morgan logs HTTP requests ('dev' format shows colored, concise output), cors enables Cross-Origin Resource Sharing for browser security (always restrict origins in production — never use cors() without options as it allows all origins), helmet sets security-related HTTP headers, and compression compresses response bodies using gzip/deflate to reduce payload size.

Custom Middleware
// Authentication middleware
const jwt = require('jsonwebtoken');

const requireAuth = (req, res, next) => {
  const token = req.headers.authorization?.split(' ')[1];
  
  if (!token) {
    return res.status(401).json({ error: 'No token provided' });
  }
  
  // Verify token
  try {
    const decoded = jwt.verify(token, process.env.JWT_SECRET);
    req.user = decoded;
    next();
  } catch (err) {
    res.status(403).json({ error: 'Invalid token' });
  }
};

// Request timing middleware
const requestTime = (req, res, next) => {
  req.requestTime = Date.now();
  next();
};

// Usage
app.use(requestTime);
app.get('/protected', requireAuth, (req, res) => {
  res.json({ message: 'Protected data', requestTime: req.requestTime });
});

Explanation: Custom middleware allows you to add application-specific logic. The requireAuth middleware checks for authentication tokens and either blocks unauthorized requests or calls next() to proceed. The requestTime middleware adds custom properties to the request object. Middleware can be applied globally with app.use() or to specific routes as function arguments.

Error-Handling Middleware
// Must have 4 parameters!
app.use((err, req, res, next) => {
  console.error(err.stack);
  res.status(err.status || 500).json({
    error: {
      message: err.message,
      ...(process.env.NODE_ENV === 'development' && { stack: err.stack })
    }
  });
});

Explanation: Error-handling middleware must have 4 parameters: (err, req, res, next). Express recognizes this signature and only calls it when an error occurs (via next(err) or thrown exceptions). This middleware should be defined last, after all routes and other middleware. The spread operator conditionally includes the stack trace only in development mode for security.

6. Request & Response Objects

Request Object (req)
app.get('/demo', (req, res) => {
  // URL parameters
  const id = req.params.id;
  
  // Query strings
  const search = req.query.q;
  
  // Request body (with body-parser)
  const data = req.body;
  
  // Headers
  const userAgent = req.get('User-Agent');
  const auth = req.headers.authorization;
  
  // Cookies (requires cookie-parser)
  const sessionId = req.cookies.sessionId;
  
  // Route path
  const path = req.path;        // '/demo'
  const hostname = req.hostname; // 'localhost'
  const protocol = req.protocol; // 'http'
  
  // HTTP method
  const method = req.method;     // 'GET'
  
  // IP address
  const ip = req.ip;
  
  res.json({ id, search, path, method });
});

Explanation: The req object represents the HTTP request and provides access to all request data. Key properties include req.params for URL parameters, req.query for query strings, req.body for parsed request bodies (requires middleware), req.headers or req.get() for headers, and metadata like req.path, req.method, and req.ip.

Response Methods
// Send different response types
app.get('/api/examples', (req, res) => {
  // JSON response
  res.json({ status: 'success', data: [] });
  
  // Send string
  res.send('Hello');
  
  // Set status code
  res.status(404).send('Not found');
  
  // Redirect
  res.redirect('/new-url');
  res.redirect(301, '/moved-permanently');
  
  // Download file
  res.download('/path/to/file.pdf');
  
  // Send file
  res.sendFile(__dirname + '/index.html');
  
  // Set headers
  res.set('Content-Type', 'application/json');
  res.set({
    'Content-Type': 'text/plain',
    'X-Custom-Header': 'value'
  });
  
  // Render template
  res.render('index', { title: 'Home' });
  
  // End response
  res.end();
});

Explanation: The res object provides methods to send responses: res.json() sends JSON (automatically sets Content-Type), res.send() sends various types (strings, buffers, objects), res.status() sets HTTP status codes, res.redirect() redirects to different URLs, res.download() and res.sendFile() send files, res.render() renders templates, and res.set() sets custom headers.

Status Codes
res.sendStatus(200); // OK
res.sendStatus(201); // Created
res.sendStatus(204); // No Content
res.sendStatus(400); // Bad Request
res.sendStatus(401); // Unauthorized
res.sendStatus(403); // Forbidden
res.sendStatus(404); // Not Found
res.sendStatus(500); // Internal Server Error

Explanation: res.sendStatus() sets the status code and sends its string representation as the response body. Common codes: 2xx (success), 4xx (client errors like 404 Not Found, 401 Unauthorized), and 5xx (server errors like 500 Internal Server Error). For more control, use res.status(code).json(data) to send a status with custom response data.

7. Error Handling

Basic Error Handling
// Synchronous errors
app.get('/sync-error', (req, res) => {
  throw new Error('Something went wrong!'); // Caught by Express
});

// Asynchronous errors (use try-catch or pass to next)
app.get('/async-error', async (req, res, next) => {
  try {
    const data = await someAsyncOperation();
    res.json(data);
  } catch (error) {
    next(error); // Pass to error handler
  }
});

Explanation: Express automatically catches synchronous errors thrown in route handlers, but asynchronous errors must be explicitly passed to error handlers using next(error). For async/await functions, wrap code in try-catch blocks and call next(error) in the catch block to ensure errors are properly handled.

Custom Error Class
class AppError extends Error {
  constructor(message, statusCode) {
    super(message);
    this.statusCode = statusCode;
    this.isOperational = true;
    Error.captureStackTrace(this, this.constructor);
  }
}

// Usage
app.get('/user/:id', async (req, res, next) => {
  const user = await User.findById(req.params.id);
  if (!user) {
    return next(new AppError('User not found', 404));
  }
  res.json(user);
});

Explanation: Creating a custom error class extends the built-in Error class with additional properties like statusCode and isOperational. This helps distinguish operational errors (expected, like "user not found") from programmer errors (bugs). Error.captureStackTrace() maintains a clean stack trace that excludes the error class constructor itself.

Global Error Handler
// 404 handler
app.use((req, res, next) => {
  res.status(404).json({
    error: 'Route not found',
    path: req.originalUrl
  });
});

// Global error handler (must be last!)
app.use((err, req, res, next) => {
  const statusCode = err.statusCode || 500;
  const message = err.message || 'Internal Server Error';
  
  console.error(`[ERROR] ${statusCode} - ${message}`);
  console.error(err.stack);
  
  res.status(statusCode).json({
    error: {
      message,
      ...(process.env.NODE_ENV === 'development' && {
        stack: err.stack,
        details: err
      })
    }
  });
});

Explanation: The 404 handler middleware catches all requests that don't match any routes (place before the error handler). The global error handler catches all errors passed via next(err) or thrown exceptions. It logs errors, determines the status code, and sends a JSON response. Sensitive information like stack traces should only be included in development environments.

Async Error Wrapper
// Utility to catch async errors
const asyncHandler = (fn) => (req, res, next) => {
  Promise.resolve(fn(req, res, next)).catch(next);
};

// Usage
app.get('/users', asyncHandler(async (req, res) => {
  const users = await User.find();
  res.json(users); // No try-catch needed!
}));

Explanation: The asyncHandler utility wraps async route handlers and automatically catches rejected promises, passing them to next(). This eliminates repetitive try-catch blocks in every async route. Promise.resolve() ensures the function result is treated as a promise, and .catch(next) forwards any errors to the error handler.

8. Template Engines

Setup (EJS Example)
npm install ejs
// app.js
app.set('view engine', 'ejs');
app.set('views', './views');

app.get('/', (req, res) => {
  res.render('index', { 
    title: 'Home Page',
    users: ['Alice', 'Bob', 'Charlie']
  });
});

Explanation: app.set('view engine', 'ejs') configures Express to use EJS templates. app.set('views', './views') specifies the directory containing templates. res.render() renders a template by name and passes data as the second argument, which becomes available as variables in the template.

EJS Template (views/index.ejs)
<!DOCTYPE html>
<html>
<head>
  <title><%= title %></title>
</head>
<body>
  <h1><%= title %></h1>
  <ul>
    <% users.forEach(user => { %>
      <li><%= user %></li>
    <% }) %>
  </ul>
</body>
</html>

Explanation: EJS (Embedded JavaScript) templates use <%= variable %> to output values (HTML-escaped) and <% code %> for control flow. The template has access to all variables passed via res.render(). EJS supports JavaScript syntax within templates, making it powerful for dynamic content generation.

Pug (Jade) Example
npm install pug
app.set('view engine', 'pug');
// views/index.pug
html
  head
    title= title
  body
    h1= title
    ul
      each user in users
        li= user

Explanation: Pug (formerly Jade) uses indentation-based syntax without closing tags. title= variable outputs the value, and each item in array iterates over arrays. Pug is more concise than EJS but has a steeper learning curve. Choose based on team familiarity and preference.

9. Static Files

// Serve files from 'public' directory
app.use(express.static('public'));
// Access: http://localhost:3000/css/style.css

// Virtual path prefix
app.use('/static', express.static('public'));
// Access: http://localhost:3000/static/css/style.css

// Multiple static directories
app.use(express.static('public'));
app.use(express.static('files'));

// Absolute path (recommended)
const path = require('path');
app.use(express.static(path.join(__dirname, 'public')));

Explanation: express.static() serves files from a directory. Files are served relative to the static directory (e.g., public/css/style.css is accessed at /css/style.css). Virtual path prefixes like app.use('/static', express.static('public')) require the prefix in URLs. Multiple static directories can be mounted, with Express searching them in order. Using path.join(__dirname, 'public') ensures absolute paths work correctly.

10. Express Router

Creating Modular Routes

routes/users.js:

const express = require('express');
const router = express.Router();

// Middleware specific to this router
router.use((req, res, next) => {
  console.log('User route accessed:', Date.now());
  next();
});

// GET /users
router.get('/', (req, res) => {
  res.json({ users: [] });
});

// GET /users/:id
router.get('/:id', (req, res) => {
  res.json({ userId: req.params.id });
});

// POST /users
router.post('/', (req, res) => {
  res.status(201).json({ message: 'User created' });
});

module.exports = router;

Explanation: express.Router() creates modular, mountable route handlers. Each router is a mini-application with its own middleware and routes. Middleware defined with router.use() only runs for routes within that router. Route paths are relative to the mount point (e.g., router.get('/') becomes /users when mounted with app.use('/users', usersRouter)).

app.js:

const usersRouter = require('./routes/users');
const postsRouter = require('./routes/posts');

app.use('/users', usersRouter);
app.use('/posts', postsRouter);
Route Parameters in Router
// Param middleware
router.param('userId', (req, res, next, userId) => {
  // Validate or fetch user
  console.log('User ID:', userId);
  req.userId = userId;
  next();
});

router.get('/:userId', (req, res) => {
  res.json({ userId: req.userId });
});

Explanation: router.param() adds middleware that runs whenever a specific parameter is present in a route. This is useful for parameter validation, loading resources from databases, or transforming parameter values. The middleware receives the parameter value as the fourth argument and can attach data to req for use in subsequent handlers.

models/Todo.js:

// In-memory storage (use DB in production)
let todos = [
  { id: 1, title: 'Learn Express', completed: false },
  { id: 2, title: 'Build REST API', completed: false }
];
let nextId = 3;

class Todo {
  static findAll() {
    return todos;
  }

  static findById(id) {
    return todos.find(t => t.id === parseInt(id));
  }

  static create(data) {
    const todo = { id: nextId++, ...data, completed: false };
    todos.push(todo);
    return todo;
  }

  static update(id, data) {
    const index = todos.findIndex(t => t.id === parseInt(id));
    if (index === -1) return null;
    todos[index] = { ...todos[index], ...data };
    return todos[index];
  }

  static delete(id) {
    const index = todos.findIndex(t => t.id === parseInt(id));
    if (index === -1) return false;
    todos.splice(index, 1);
    return true;
  }
}

module.exports = Todo;

Explanation: This simple Todo model uses in-memory storage (an array) and provides static methods for CRUD operations. findAll() returns all todos, findById() searches by ID, create() adds new todos with auto-incrementing IDs, update() modifies existing todos, and delete() removes them. In production, replace this with a database model (Sequelize, Mongoose, etc.).

controllers/todoController.js:

const Todo = require('../models/Todo');

exports.getAllTodos = (req, res) => {
  const todos = Todo.findAll();
  res.json({ count: todos.length, data: todos });
};

exports.getTodoById = (req, res, next) => {
  const todo = Todo.findById(req.params.id);
  if (!todo) {
    return res.status(404).json({ error: 'Todo not found' });
  }
  res.json({ data: todo });
};

exports.createTodo = (req, res) => {
  const { title } = req.body;
  
  if (!title || title.trim() === '') {
    return res.status(400).json({ error: 'Title is required' });
  }
  
  const todo = Todo.create({ title: title.trim() });
  res.status(201).json({ message: 'Todo created', data: todo });
};

exports.updateTodo = (req, res) => {
  const { title, completed } = req.body;
  const todo = Todo.update(req.params.id, { title, completed });
  
  if (!todo) {
    return res.status(404).json({ error: 'Todo not found' });
  }
  
  res.json({ message: 'Todo updated', data: todo });
};

exports.deleteTodo = (req, res) => {
  const deleted = Todo.delete(req.params.id);
  
  if (!deleted) {
    return res.status(404).json({ error: 'Todo not found' });
  }
  
  res.json({ message: 'Todo deleted' });
};

Explanation: Controllers contain the business logic for each route. They interact with models to perform operations and send responses. getAllTodos() retrieves all items, getTodoById() finds one item and returns 404 if not found, createTodo() validates input and creates new items (201 Created status), updateTodo() modifies items, and deleteTodo() removes items. Validation ensures data integrity before database operations.

routes/todos.js:

const express = require('express');
const router = express.Router();
const todoController = require('../controllers/todoController');

router.get('/', todoController.getAllTodos);
router.get('/:id', todoController.getTodoById);
router.post('/', todoController.createTodo);
router.put('/:id', todoController.updateTodo);
router.delete('/:id', todoController.deleteTodo);

module.exports = router;

Explanation: Route files define URL paths and HTTP methods, delegating business logic to controllers. This separation follows the MVC pattern: routes handle routing, controllers contain logic, and models manage data. Using express.Router() and controller methods keeps route definitions clean and readable. Each route corresponds to a RESTful operation (GET for retrieval, POST for creation, PUT for updates, DELETE for deletion).

middleware/errorHandler.js:

module.exports = (err, req, res, next) => {
  console.error(err.stack);
  
  const statusCode = err.statusCode || 500;
  const message = err.message || 'Internal Server Error';
  
  res.status(statusCode).json({
    error: message,
    ...(process.env.NODE_ENV === 'development' && { stack: err.stack })
  });
};

Explanation: Centralizing error handling in a single middleware ensures consistent error responses across the application. It logs errors for debugging, extracts status codes and messages from error objects (with fallbacks), and conditionally includes stack traces in development. This middleware should be exported and registered last in app.js using app.use(errorHandler).

Explanation: These curl commands demonstrate testing each API endpoint. -X specifies the HTTP method, -H sets headers (Content-Type for JSON), and -d sends request body data. GET requests retrieve data, POST creates resources (returns 201), PUT updates entire resources, PATCH makes partial updates, and DELETE removes resources. Always test error cases like invalid IDs (404) and missing required fields (400).
