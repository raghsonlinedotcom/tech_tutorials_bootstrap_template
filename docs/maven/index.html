Introduction to Apache Maven

Apache Maven is a powerful build automation and project management tool primarily used for Java projects. It simplifies the build process, manages dependencies, and provides a uniform build system.

What is Apache Maven?

Maven is based on the Project Object Model (POM) concept and provides developers with:

  • Dependency Management: Automatically download and manage project dependencies
  • Standardized Build: Convention over configuration approach
  • Plugin Architecture: Extend functionality through plugins
  • Project Lifecycle: Well-defined phases for building, testing, and deploying
  • Repository Management: Central and local repository systems
Latest Version: Maven 3.9.6 (as of January 2026) with Java 17+ support. Maven 4.0 is in development with performance improvements and new features.

Why Use Maven?

Simplified Build Process

No need to write complex build scripts - Maven handles compilation, testing, packaging automatically.

Dependency Management

Automatic resolution and download of dependencies and transitive dependencies.

Plugin Ecosystem

Rich ecosystem of plugins for various tasks - testing, code quality, deployment, and more.

Industry Standard

Widely adopted in the Java ecosystem, making projects easy to understand and maintain.

Key Architecture Elements

1. Project Object Model (POM)

The pom.xml file is the heart of a Maven project. It contains:

  • Project coordinates (groupId, artifactId, version)
  • Dependencies and their versions
  • Build configuration and plugins
  • Project properties and profiles
2. Maven Repositories
Local Repository: ~/.m2/repository - Caches downloaded dependencies
Central Repository: https://repo.maven.apache.org/maven2 - Public Maven artifacts
Remote Repositories: Custom/private repositories (Nexus, Artifactory)
3. Plugin Architecture

Maven is essentially a plugin execution framework. Everything is done through plugins:

  • maven-compiler-plugin - Compiles Java source code
  • maven-surefire-plugin - Runs unit tests
  • maven-jar-plugin - Creates JAR files
  • maven-deploy-plugin - Deploys artifacts to repositories
4. Standard Directory Structure

│   │   ├── java/          # Java source files

│   └── test/

    ├── classes/           # Compiled classes
    ├── test-classes/      # Compiled test classes
    ├── surefire-reports/  # Test reports
    └── *.jar              # Final artifact

Maven Build Lifecycle

Maven has three built-in lifecycles: default (build), clean (cleanup), and site (documentation).

Default Lifecycle Phases

The default lifecycle consists of 23 phases. Here are the most important ones:

Phase Description Key Actions
validate Validate project structure Check if project is correct and all necessary information is available
compile Compile source code Compile Java files from src/main/java to target/classes
test Run unit tests Execute tests using Surefire plugin, generate reports
package Create distributable format Package compiled code (JAR, WAR, etc.)
verify Run integration tests Execute integration tests and quality checks
install Install to local repository Copy artifact to ~/.m2/repository for use in other projects
deploy Deploy to remote repository Copy artifact to remote repository for sharing
Important: When you execute a phase, all previous phases are executed automatically. For example, mvn package runs validate, compile, test, and then package.

POM (Project Object Model) Structure

The pom.xml file is the fundamental unit of work in Maven. It contains all project configuration.

Basic POM Structure

<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0
         http://maven.apache.org/xsd/maven-4.0.0.xsd">
    
    <!-- POM model version (always 4.0.0 for Maven 3.x) -->
    <modelVersion>4.0.0</modelVersion>
    
    <!-- Project Coordinates - Unique identifier -->
    <groupId>com.example</groupId>
    <artifactId>my-project</artifactId>
    <version>1.0.0</version>
    <packaging>jar</packaging>
    
    <!-- Project Information -->
    <name>My Project</name>
    <description>A sample Maven project</description>
    <url>https://example.com/my-project</url>
    
    <!-- Properties -->
    <properties>
        <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
        <maven.compiler.source>17</maven.compiler.source>
        <maven.compiler.target>17</maven.compiler.target>
        <junit.version>5.10.1</junit.version>
    </properties>
    
    <!-- Dependencies -->
    <dependencies>
        <dependency>
            <groupId>org.junit.jupiter</groupId>
            <artifactId>junit-jupiter</artifactId>
            <version>${junit.version}</version>
            <scope>test</scope>
        </dependency>
    </dependencies>
    
    <!-- Build Configuration -->
    <build>
        <plugins>
            <plugin>
                <groupId>org.apache.maven.plugins</groupId>
                <artifactId>maven-compiler-plugin</artifactId>
                <version>3.11.0</version>
                <configuration>
                    <source>17</source>
                    <target>17</target>
                </configuration>
            </plugin>
        </plugins>
    </build>
    
</project>

Key POM Elements

1. Project Coordinates (GAV)
  • groupId: Organization/company identifier (reverse domain)
  • artifactId: Project name (unique within group)
  • version: Project version (MAJOR.MINOR.PATCH)
2. Dependency Scopes
Scope Description Example
compile Default scope, available everywhere Spring Framework, Apache Commons
test Only for testing phase JUnit, Mockito
provided Provided by runtime (not packaged) Servlet API (provided by server)
runtime Not needed for compilation, only runtime JDBC drivers
3. Parent POM & Inheritance

Projects can inherit from a parent POM to share configuration:

<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>3.2.1</version>
</parent>
4. Dependency Management

Define versions centrally without adding dependencies:

<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>org.junit</groupId>
            <artifactId>junit-bom</artifactId>
            <version>5.10.1</version>
            <type>pom</type>
            <scope>import</scope>

The Book class represents a book entity with all relevant properties.

package com.library.model;

import lombok.AllArgsConstructor;
import lombok.Data;
import lombok.NoArgsConstructor;

import java.time.LocalDate;

/**
 * Represents a book in the library system.
 * Uses Lombok annotations to reduce boilerplate code.
 */
@Data
@NoArgsConstructor
@AllArgsConstructor
public class Book {
    private String isbn;
    private String title;
    private String author;
    private String category;
    private int publicationYear;
    private boolean available;
    private String borrowedBy;
    private LocalDate borrowedDate;
    
    /**
     * Constructor for creating a new book (initially available)
     */
    public Book(String isbn, String title, String author, String category, int publicationYear) {
        this.isbn = isbn;
        this.title = title;
        this.author = author;
        this.category = category;
        this.publicationYear = publicationYear;
        this.available = true;
    }
    
    /**
     * Mark book as borrowed by a user
     */
    public void borrow(String userId) {
        this.available = false;
        this.borrowedBy = userId;
        this.borrowedDate = LocalDate.now();
    }
    
    /**
     * Mark book as returned
     */
    public void returnBook() {
        this.available = true;
        this.borrowedBy = null;
        this.borrowedDate = null;
    }
}
Key Points:
  • @Data: Lombok generates getters, setters, toString, equals, and hashCode
  • @NoArgsConstructor/@AllArgsConstructor: Generate constructors
  • Business methods: borrow() and returnBook() manage book state
  • LocalDate: Java 8+ date API for tracking borrow dates

The User class represents a library user/member.

package com.library.model;

import lombok.AllArgsConstructor;
import lombok.Data;
import lombok.NoArgsConstructor;

import java.util.ArrayList;
import java.util.List;

/**
 * Represents a library user/member
 */
@Data
@NoArgsConstructor
@AllArgsConstructor
public class User {
    private String userId;
    private String name;
    private String email;
    private String phone;
    private List borrowedBooks;
    
    /**
     * Constructor for creating a new user
     */
    public User(String userId, String name, String email, String phone) {
        this.userId = userId;
        this.name = name;
        this.email = email;
        this.phone = phone;
        this.borrowedBooks = new ArrayList<>();
    }
    
    /**
     * Add a borrowed book to user's list
     */
    public void addBorrowedBook(String isbn) {
        if (borrowedBooks == null) {
            borrowedBooks = new ArrayList<>();
        }
        borrowedBooks.add(isbn);
    }
    
    /**
     * Remove a returned book from user's list
     */
    public void removeBorrowedBook(String isbn) {
        if (borrowedBooks != null) {
            borrowedBooks.remove(isbn);
        }
    }
    
    /**
     * Check if user can borrow more books (limit: 5 books)
     */
    public boolean canBorrowMore() {
        return borrowedBooks == null || borrowedBooks.size() < 5;
    }
}
Key Points:
  • borrowedBooks: Tracks ISBNs of books currently borrowed
  • canBorrowMore(): Business rule limiting books to 5 per user
  • Defensive programming: Null checks in methods

Service for persisting data to JSON files using Jackson.

package com.library.service;

import com.fasterxml.jackson.databind.ObjectMapper;
import com.fasterxml.jackson.databind.SerializationFeature;
import com.fasterxml.jackson.datatype.jsr310.JavaTimeModule;
import com.library.exception.LibraryException;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

import java.io.File;
import java.io.IOException;
import java.util.ArrayList;
import java.util.List;

/**
 * Service for storing and retrieving data from JSON files
 */
public class StorageService {
    private static final Logger logger = LoggerFactory.getLogger(StorageService.class);
    private final ObjectMapper objectMapper;
    private final Class type;
    
    public StorageService(Class type) {
        this.type = type;
        this.objectMapper = new ObjectMapper();
        // Enable Java 8 date/time support
        this.objectMapper.registerModule(new JavaTimeModule());
        this.objectMapper.enable(SerializationFeature.INDENT_OUTPUT);
    }
    
    /**
     * Save list of objects to a JSON file
     */
    public void save(List items, String filePath) throws LibraryException {
        try {
            File file = new File(filePath);
            file.getParentFile().mkdirs(); // Create directories if needed
            objectMapper.writeValue(file, items);
            logger.info("Saved {} items to {}", items.size(), filePath);
        } catch (IOException e) {
            logger.error("Failed to save data to {}", filePath, e);
            throw new LibraryException("Failed to save data", e);
        }
    }
    
    /**
     * Load list of objects from a JSON file
     */
    public List load(String filePath) throws LibraryException {
        try {
            File file = new File(filePath);
            if (!file.exists()) {
                logger.warn("File {} does not exist, returning empty list", filePath);
                return new ArrayList<>();
            }
            
            List items = objectMapper.readValue(
                file,
                objectMapper.getTypeFactory().constructCollectionType(List.class, type)
            );
            logger.info("Loaded {} items from {}", items.size(), filePath);
            return items;
        } catch (IOException e) {
            logger.error("Failed to load data from {}", filePath, e);
            throw new LibraryException("Failed to load data", e);
        }
    }
}
Key Points:
  • Generic class: Works with any type (Book, User)
  • Jackson ObjectMapper: Handles JSON serialization/deserialization
  • JavaTimeModule: Support for LocalDate serialization
  • SLF4J logging: Structured logging throughout

    private final StorageService bookStorage;
    private final StorageService userStorage;
    
    public LibraryService() {
        this.books = new ArrayList<>();
        this.users = new ArrayList<>();
        this.bookStorage = new StorageService<>(Book.class);
        this.userStorage = new StorageService<>(User.class);
    }
    
    /**
     * Load data from storage
     */
    public void loadData() throws LibraryException {
        this.books = bookStorage.load(BOOKS_FILE);
        this.users = userStorage.load(USERS_FILE);
        logger.info("Loaded {} books and {} users", books.size(), users.size());
    }
    
    /**
     * Save data to storage
     */
    public void saveData() throws LibraryException {
        bookStorage.save(books, BOOKS_FILE);
        userStorage.save(users, USERS_FILE);
        logger.info("Saved {} books and {} users", books.size(), users.size());
    }
    
    /**
     * Add a new book to the library
     */
    public void addBook(Book book) throws LibraryException {
        if (findBookByIsbn(book.getIsbn()).isPresent()) {
            throw new LibraryException("Book with ISBN " + book.getIsbn() + " already exists");
        }
        books.add(book);
        logger.info("Added book: {}", book.getTitle());
    }
    
    /**
     * Register a new user
     */
    public void addUser(User user) throws LibraryException {
        if (findUserById(user.getUserId()).isPresent()) {
            throw new LibraryException("User with ID " + user.getUserId() + " already exists");
        }
        users.add(user);
        logger.info("Registered user: {}", user.getName());
    }
    
    /**
     * Find book by ISBN
     */
    public Optional findBookByIsbn(String isbn) {
        return books.stream()
                .filter(book -> book.getIsbn().equals(isbn))
                .findFirst();
    }
    
    /**
     * Find user by ID
     */
    public Optional findUserById(String userId) {
        return users.stream()
                .filter(user -> user.getUserId().equals(userId))
                .findFirst();
    }
    
    /**
     * Search books by title (case-insensitive partial match)
     */
    public List searchBooksByTitle(String title) {
        return books.stream()
                .filter(book -> book.getTitle().toLowerCase().contains(title.toLowerCase()))
                .collect(Collectors.toList());
    }
    
    /**
     * Search books by author
     */
    public List searchBooksByAuthor(String author) {
        return books.stream()
                .filter(book -> book.getAuthor().toLowerCase().contains(author.toLowerCase()))
                .collect(Collectors.toList());
    }
    
    /**
     * Get all available books
     */
    public List getAvailableBooks() {
        return books.stream()
                .filter(Book::isAvailable)
                .collect(Collectors.toList());
    }
    
    /**
     * Borrow a book
     */
    public void borrowBook(String isbn, String userId) throws LibraryException {
        Book book = findBookByIsbn(isbn)
                .orElseThrow(() -> new LibraryException("Book not found: " + isbn));
        
        User user = findUserById(userId)
                .orElseThrow(() -> new LibraryException("User not found: " + userId));
        
        if (!book.isAvailable()) {
            throw new LibraryException("Book is not available: " + book.getTitle());
        }
        
        if (!user.canBorrowMore()) {
            throw new LibraryException("User has reached borrowing limit");
        }
        
        book.borrow(userId);
        user.addBorrowedBook(isbn);
        logger.info("User {} borrowed book {}", user.getName(), book.getTitle());
    }
    
    /**
     * Return a book
     */
    public void returnBook(String isbn) throws LibraryException {
        Book book = findBookByIsbn(isbn)
                .orElseThrow(() -> new LibraryException("Book not found: " + isbn));
        
        if (book.isAvailable()) {
            throw new LibraryException("Book was not borrowed: " + book.getTitle());
        }
        
        String userId = book.getBorrowedBy();
        User user = findUserById(userId)
                .orElseThrow(() -> new LibraryException("User not found: " + userId));
        
        book.returnBook();
        user.removeBorrowedBook(isbn);
        logger.info("User {} returned book {}", user.getName(), book.getTitle());
    }
    
    /**
     * Get statistics
     */
    public String getStatistics() {
        long totalBooks = books.size();
        long availableBooks = books.stream().filter(Book::isAvailable).count();
        long borrowedBooks = totalBooks - availableBooks;
        long totalUsers = users.size();
        
        return String.format(
            "Library Statistics:%n" +
            "Total Books: %d%n" +
            "Available: %d%n" +
            "Borrowed: %d%n" +
            "Total Users: %d",
            totalBooks, availableBooks, borrowedBooks, totalUsers
        );
    }
    
    // Getters
    public List getAllBooks() {
        return new ArrayList<>(books);
    }
    
    public List getAllUsers() {
        return new ArrayList<>(users);
    }
}

Field Design Decisions

  • LocalDate: Java 8+ Date-Time API - immutable, thread-safe, no millisecond precision needed for borrow dates

public void borrowBook(String userId, String isbn) throws LibraryException {
    // 1. Validate user exists
    User user = users.stream()
        .filter(u -> u.getUserId().equals(userId))
        .findFirst()
        .orElseThrow(() -> new LibraryException("User not found: " + userId));
    
    // 2. Find book
    Book book = books.stream()
        .filter(b -> b.getIsbn().equals(isbn))
        .findFirst()
        .orElseThrow(() -> new LibraryException("Book not found: " + isbn));
    
    // 3. Check availability
    if (!book.isAvailable()) {
        throw new LibraryException("Book is already borrowed: " + book.getTitle());
    }
    
    // 4. Execute borrow (state changes)
    book.borrow(userId);
    user.getBorrowedBooks().add(isbn);
    
    // 5. Persist changes
    storage.saveBooks(books);
    storage.saveUsers(users);
    
    // 6. Log operation
    logger.info("User {} borrowed book {}", user.getName(), book.getTitle());
}

Dockerfile Explained

We'll use a multi-stage Docker build for efficiency - one stage for building, another for running.

Complete Dockerfile
# Stage 1: Build Stage
# Use official Maven image with JDK 17
FROM maven:3.9.6-eclipse-temurin-17 AS build

# Set working directory
WORKDIR /app

# Copy pom.xml first (for better layer caching)
COPY pom.xml .

# Download dependencies (cached if pom.xml hasn't changed)
RUN mvn dependency:go-offline -B

# Copy source code
COPY src ./src

# Build the application (skip tests for faster builds, or remove -DskipTests)
RUN mvn clean package -DskipTests

# Stage 2: Runtime Stage
# Use smaller JRE-only image for runtime
FROM eclipse-temurin:17-jre-alpine

# Set working directory
WORKDIR /app

# Create non-root user for security
RUN addgroup -S appgroup && adduser -S appuser -G appgroup

# Copy JAR from build stage
COPY --from=build /app/target/library-management-system-1.0.0.jar app.jar

# Create directory for data files
RUN mkdir -p /app/data && chown -R appuser:appgroup /app

# Switch to non-root user
USER appuser

# Expose port (if your app needs it)
# EXPOSE 8080

# Run the application
ENTRYPOINT ["java", "-jar", "app.jar"]
Dockerfile Line-by-Line Explanation

FROM maven:3.9.6-eclipse-temurin-17 AS build

  • Base image includes both Maven 3.9.6 and JDK 17
  • eclipse-temurin is the official open-source JDK
  • AS build names this stage for reference in stage 2

WORKDIR /app

  • Sets working directory inside container to /app
  • All subsequent commands execute in this directory

COPY pom.xml .

  • Copy pom.xml FIRST (before source code)
  • Docker caches layers - if pom.xml unchanged, dependency download is cached
  • Significantly speeds up rebuilds

RUN mvn dependency:go-offline -B

  • Downloads all dependencies defined in pom.xml
  • -B flag runs in batch mode (non-interactive)
  • This layer is cached unless pom.xml changes

COPY src ./src

  • Copy source code after dependencies are downloaded
  • Source changes won't invalidate dependency cache

RUN mvn clean package -DskipTests

  • Build the application: compile, test, package
  • -DskipTests skips tests (remove to run tests in Docker)
  • Produces JAR in /app/target/

FROM eclipse-temurin:17-jre-alpine

  • Starts fresh with smaller JRE-only image (no Maven, no JDK tools)
  • alpine is a minimal Linux distribution (~5MB base)
  • Final image is ~200MB vs ~600MB with full JDK

RUN addgroup -S appgroup && adduser -S appuser -G appgroup

  • Security best practice: don't run as root
  • Creates non-root user for running the application

COPY --from=build /app/target/*.jar app.jar

  • --from=build copies from Stage 1
  • Only the compiled JAR is copied, not source code or build tools

USER appuser

  • Switch from root to non-privileged user
  • Application runs with limited permissions

ENTRYPOINT ["java", "-jar", "app.jar"]

  • Defines the command to run when container starts
  • Exec form (JSON array) ensures proper signal handling

Image Size Comparison:
Approach Image Size Contents
Single-stage (JDK + Maven) ~600-800 MB JDK, Maven, source code, dependencies, build tools
Multi-stage (JRE only) ~200-250 MB JRE, compiled JAR only
Savings ~400-550 MB (60-70%) Faster deploys, less storage, reduced attack surface
Security Benefits:
  • No build tools (Maven, compilers) in production image
  • No source code in final image
  • Smaller attack surface - fewer packages to exploit
  • Non-root user execution

Frequently Asked Questions

mvn clean package creates the JAR/WAR file in the target/ directory.

mvn clean install does the same but also copies the artifact to your local Maven repository (~/.m2/repository), making it available to other projects on your machine.

Use package for normal development. Use install when you want other local projects to depend on this project.

You can skip tests in two ways:

# Skip test execution but compile them
mvn package -DskipTests

# Skip test compilation and execution
mvn package -Dmaven.test.skip=true
⚠️ Warning: Skipping tests is not recommended for production builds. Use only for quick local builds during development.

Maven uses "nearest definition" strategy. If two versions of the same dependency are found, the one closest to the project in the dependency tree wins.

View dependency tree:
mvn dependency:tree
