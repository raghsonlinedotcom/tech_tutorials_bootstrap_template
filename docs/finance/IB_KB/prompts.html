01 WHY THIS FILE EXISTS

Claude has no memory between sessions. Every new conversation starts completely blank — no knowledge of previous modules built, no awareness of the design system established, no recollection of decisions made. Without a structured prompt, a new session will:

Without this file

Wrong colour palette · Wrong fonts · Mermaid syntax errors from rushing · Pure CSS flowcharts substituted · Missing ECM/DCM coverage · No FAQ or Version History · Inconsistent section structure · No awareness of prior modules

With this file

Full design system inherited · Correct diagramming tool per use case · ECM and DCM coverage enforced · FAQ accordion and Version History mandatory · Module cross-references intact · Session history understood · Zero regressions

📌 The core principle
Each prompt is fully self-contained. It carries everything a fresh Claude session needs to produce output consistent with all prior modules — with no reliance on this thread, no memory, and no assumptions.

03 MASTER DIAGRAMMING RULES

These rules apply to every module. They were established after repeated Mermaid syntax failures in early sessions where diagrams were rushed — emojis inside node labels, line breaks inside quotes, and pure CSS boxes used as fallbacks. All three are now explicitly banned.

USE CASE CORRECT TOOL REASON
Process flows Mermaid flowchart TD/LR Proper graph layout, curved edges, maintainable syntax
Decision trees Mermaid flowchart with diamond nodes Clean branching, labeled edges, readable at scale
Org charts / entity maps Mermaid flowchart or graph Hierarchy rendering built-in
Sequence / state diagrams Mermaid sequenceDiagram / stateDiagram Native support; no workaround needed
Side-by-side matrices ASCII — pre block with .ascii class Mermaid cannot do side-by-side well; ASCII is genuinely superior here
Comparison tables ASCII or HTML .tbl table Both render cleanly; .tbl preferred for hover/striping
Stage pipelines CSS .pipeline component Arrow-connected stage boxes — works well, established in M01
Data charts (bar/line) Chart.js — M06 only Economics module needs interactive data viz; CDN available
Simple annotated layouts ASCII Fastest, most reliable for annotated box diagrams
Pure CSS flowcharts BANNED — never use Trades Mermaid syntax errors for brittle layout bugs; not professional

▸ MERMAID NON-NEGOTIABLE RULES

MERMAID RULES — VIOLATION = BROKEN DIAGRAM ═══════════════════════════════════════════════════════════════════════════════ RULE 1 CDN must be: https://cdn.jsdelivr.net/npm/mermaid@10/dist/mermaid.min.js RULE 2 Initialise exactly as: mermaid.initialize({startOnLoad:true, theme:'dark', themeVariables:{primaryColor:'#1e3a5f', primaryTextColor:'#e2e8f0', lineColor:'#d4af37', fontFamily:'JetBrains Mono, monospace'}}) RULE 3 ZERO emojis inside node labels BAD: A["Cleared? ✓"] GOOD: A["Cleared"] RULE 4 ZERO Unicode / special chars inside node labels BAD: B["Step → Next"] GOOD: B["Step to Next"] RULE 5 ZERO \n line breaks inside node label quotes BAD: C["Deal\nOrigination"] GOOD: C["Deal Origination"] -- keep it short, put detail in caption RULE 6 Wrap every diagram in: <div class="mermaid-wrap"> <pre class="mermaid">...diagram...</pre> <div class="diagram-caption">Fig N.N — description</div> </div> RULE 7 Mentally trace every node and edge before writing the next diagram If a node is referenced but never defined, Mermaid fails silently RULE 8 Keep diagrams to <= 12 nodes for readability Split large flows into two diagrams with a shared entry/exit node ═══════════════════════════════════════════════════════════════════════════════
💡 Why pure CSS flowcharts were used before — and why they are now banned
In early sessions, repeated Mermaid syntax errors (emojis in labels, line breaks in quotes, undefined nodes) caused diagrams to render blank or broken. Rather than fix the root cause, pure CSS div-based boxes were substituted as a "safe" fallback. This was the wrong trade — it swapped syntax errors for layout brittleness. The correct fix is the 8 rules above. Pure CSS flowcharts are now permanently banned.
